Events Ticker

A static web page that, when opened, shows upcoming Luma events ranked against your criteria (match, reach, distance). No database and no runtime backend. Code is written with Claude Code, stored on GitHub and auto-deployed to Vercel.

1. Architecture

The data is fetched daily by GitHub Actions, not when someone opens the page. That keeps the site frontend-only with no keys or backend.

2. What happens when the page opens

Everything after the first request runs in the browser.

sequenceDiagram
  actor You
  participant Page as Static page on Vercel
  participant Data as events.json + criteria.json
  participant Engine as Scoring in browser
  You->>Page: Open URL
  Page->>Data: Load bundled JSON
  Data-->>Page: Upcoming events + your profile
  Page->>Engine: Score each event
  Note over Engine: match = topic overlap with profile
reach = RSVP count, host size
distance = km from home location
  Engine-->>Page: Ranked list
  Page-->>You: Ticker of top matches
  You->>Page: Adjust weights or filters
  Page->>Engine: Re-rank instantly
  You->>Page: Click Export PDF
  Page-->>You: PDF via print stylesheet or jsPDF

5. Components

PieceRoleLives in
CLAUDE.mdDevelopment plan, stack choice, conventions Claude Code follows every sessionRepo root
profile.mdYour LinkedIn profile summarized into criteria: topics, seniority, location, interestsRepo, converted to criteria.json at build
DESIGN.md / AGENTS.mdDesign tokens and thinking; instructions for any AI agent working in the repoRepo root
Luma MCPLets Claude Code look at real events while developingYour Claude Code setup
scripts/fetch-events.mjsCalls Luma's public Discover feed (same endpoint as luma-mcp, no key) and writes events.jsonGitHub Actions
Scoring engineWeighted score per event: match + reach + distanceBrowser JS
Export PDFPrint stylesheet (window.print()) or jsPDFBrowser JS
VercelHosts the static build; redeploys on every pushVercel project linked to the repo
Key constraint: a web page can't call an MCP server, and Luma's official API needs Luma Plus and only covers calendars you own. V0 therefore calls the public Discover feed that luma-mcp itself uses. It's undocumented and could change, so the fetch script fails without overwriting the last good events.json.
